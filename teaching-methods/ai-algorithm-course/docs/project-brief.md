## 1. 分组规则与分工

### 1.1 组队

- 3 人一组，自由组队后向老师登记组号（G01–G10）。
- 每人承担一个**固定角色**，三角色互不相同：

| 角色 | 职责 |
|---|---|
| 算法与脚本 | 吃透算法原理；写/调 Python 脚本；保证结果可复现 |
| 交互可视化 | 设计并实现 HTML 交互演示；保证浏览器兼容与流畅 |
| 讲解与文档 | 写原理讲解脚本；录视频；整理 README 与报告 |

### 1.2 反挂名四条证据

为避免「一人干活、两人挂名」，验收时核查以下四条，**任一不满足者，该生个人成绩乘 0.85（不影响组内他人）**：

1. `git shortlog -sne` 显示三人各有不少于 3 次 commit，且跨不少于 2 个不同日期；
2. `docs/分工表.md` 中每人认领的文件在 `git blame` 中本人行数占比不低于 50%；
3. 演示视频中三人各自出镜讲解不少于 2 分钟；
4. 答辩现场随机抽 1 人解释自己负责的代码段，答不上来即记不合格。

**W2 周末必须轮换一次角色**（三人转一圈），轮换记录写入分工表。轮换的目的是让每个人都碰到算法、交互和讲解——这也是防止挂名的手段之一。

### 1.3 撞题规则

- 同一算法最多 3 组选择；
- 撞题的组须在报告里增加**不少于 300 字**的「与另一组方案的对比」章节：数据集选取、参数配置、可视化设计三方面各说一条异同；
- 抄袭认定：交互页面与另一组的核心可视化代码高度雷同（变量改名、注释汉化不算独立工作）→ **该项目 0 分**。

## 2. 选题规则与难度系数

### 2.1 怎么打分

最终成绩不是原始分，而是：

```
最终 = min( 100 , 原始分 × K )
```

- **K 是难度系数**，选题时即锁定，中途换题须重新锁定；
- 简单题做得再好也封顶 100 分；难题做砸了也有保底（见 §6）；
- **选难题的意义**：最难题（K=1.50）原始分 67 即满分，最易题（K=1.05）要原始分 95 才满分。

### 2.2 难度系数怎么来的

每个算法按五个维度打 1–5 分，加权求和后归一化：

```
S = 0.25·M + 0.20·C + 0.25·V + 0.15·A + 0.15·R
K = 1.00 + 0.05 × floor( 2.5 × (S − 1) + 0.5 )        （K ∈ [1.05, 1.50]，步长 0.05）
```

| 维度 | 含义 | 权重 | 1 分 ↔ 5 分 |
|---|---|---|---|
| **M** 数学深度 | 推导需要的数学工具 | 0.25 | 1=四则运算有闭式解 ↔ 5=需 SDE/博弈/贝尔曼方程 |
| **C** 编程复杂度 | 从调库到手写 | 0.20 | 1=sklearn 一行 fit ↔ 5=必须依赖训练框架 |
| **V** 可视化难度 | 交互演示的实现难度 | 0.25 | 1=静态图+1 滑块 ↔ 5=真算法级动画 |
| **A** 概念抽象度 | 直觉理解的难度 | 0.15 | 1=可比作日常经验 ↔ 5=反直觉（梯度消失/KL 非对称） |
| **R** 资源支撑度 | 有没有可对照的基线（逆向：越高越难） | 0.15 | 1=有脚本+演示+数据集 ↔ 5=需自建全部验证 |

### 3.2 B. 演示视频（5 条）

1. 时长 8–12 分钟，720p 以上；
2. 结构：原理白板讲解 ≥3 分钟 → 现场拖滑块演示 ≥3 分钟 → 结果解读 ≥2 分钟；
3. 三人各自出镜讲解 ≥2 分钟（对应 §1.2 第 3 条）；
4. 现场演示必须是**真操作**，不允许放录好的动图糊弄；
5. 文件命名 `视频_G组号_算法名.mp4`，过大可只交网盘链接（写入 README）。

### 3.3 C. Python 脚本（6 条）

1. 固定随机种子 `SEED = 42`，`train_test_split` 一律 `random_state=SEED`；
2. 四段结构：模块 docstring（目的/输入/参数/种子）→ `Exp(...)` 声明 → `main(seed=SEED)` → `if __name__ == "__main__"` 守卫；
3. 数据只用 `experiments/common/data.py` 的离线数据集，或随仓库提供的 csv；
4. 结果落盘到 `results/metrics|tables|figures` 三处；
5. `requirements.txt` 写明 `numpy` / `scikit-learn` 等的确切版本；
6. 老师 clone 后**一条命令跑通**（如 `python python/exp_l3_01_pca.py`），且输出数字与 README 声明一致。

## 7. 常见踩坑（前人实测）

以下 8 条来自本课程演示开发的真实翻车记录，几乎是每届都会踩的：

1. **NMF 发散**：手写矩阵乘法把 AᵀB 与 ABᵀ 用混，结果不收敛。对策：把三种乘法写成独立函数，逐个对拍 numpy。
2. **ICA 反而不如 PCA**：白化矩阵写成 `V/√d[j]`（分母下标错），正确是 `D^(-1/2)Vᵀ`。症状是恢复率反常低。
3. **自编码器梯度爆炸**：隐层大时全批量 SGD 数值溢出成 NaN。对策：加梯度范数裁剪（超过阈值整体缩放）。
4. **RNN 任务设计失效**：设计「记忆任务」想证明梯度消失，结果 RNN 用 tanh 饱和锁存轻松绕过。对策：直接可视化梯度回传的保留率曲线，别绕道训练任务。
5. **Q-Learning 不收敛**：argmax 平局总选动作 0，agent 卡在起点撞墙；终止状态误用了 max Q(s')。对策：平局随机 + 终止目标为 0。
6. **GMM 标签错位**：聚类标签编号是任意的，跨算法比较一致率要按最优排列匹配，否则永远只有 1/K。
7. **梯度下降溢出**：学习率超过稳定上界 2/L 时损失直接 Infinity。页面上要做发散检测并显示「发散」二字，别让 NaN 直接印出来。
8. **空白画布**：演示初始化时没跑一次默认渲染，打开页面什么都没有。对策：脚本末尾必须手动调用一次 update/refresh。
